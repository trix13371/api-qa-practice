# Как читать эти автотесты

Начни с `tests/test_tasks.py`. Сервер и его подготовку можно разобрать после тестов.

## Первый тест: создать задачу и прочитать её

1. `http.get(...)` отправляет GET-запрос. Сначала проверяем, что список пуст.
2. `http.post(..., json={"title": title})` отправляет JSON для создания задачи.
3. `assert create_response.status_code == 201` проверяет код ответа. Если условие неверно, тест падает.
4. `.json()` превращает JSON ответа в объект Python: здесь это словарь.
5. `expected_task` содержит ожидаемые данные. Название берётся из отправленных нами данных, а не копируется из ответа: иначе ошибочное название могло бы остаться незамеченным.
6. Новые GET-запросы проверяют, что задача сохранена и доступна по ID.

`timeout=3` ограничивает ожидание сетевых операций. Это защита от зависания, а не проверка производительности.

## Второй тест: неверные данные

`@pytest.mark.parametrize` запускает одну функцию с тремя наборами данных:

```python
{"title": ""}    # пустое название
{"title": 123}   # число вместо строки
{}               # обязательное поле отсутствует
```

Перед неверным запросом создаётся нормальная задача и запоминается список. После запроса проверяем не только ошибку 400, но и неизменность списка: сервер не должен ни добавить неверную задачу, ни удалить правильную.

Две функции — это четыре отдельных результата pytest.

## Что такое fixture

Фикстура — подготовка и освобождение ресурсов для теста. Они находятся в `conftest.py`:

- `api_url` создаёт приложение, запускает сервер и передаёт его адрес тесту. После теста останавливает сервер. Порт `0` означает: операционная система выбирает свободный порт.
- `http` создаёт HTTP-клиент requests. `trust_env=False` отключает настройки прокси из окружения для локальных запросов.

Код до `yield` подготавливает ресурс, значение после `yield` передаётся тесту, код в `finally` освобождает ресурс даже при падении проверки.

## Откуда ожидаемый результат

Из `api-contract.md`, а не просто из текущего поведения приложения. Например, `@@@` не запрещено этим контрактом: нельзя объявлять его ошибкой без такого требования.

## Упражнение после разбора

Добавь проверку `GET /tasks/999` на пустом сервере. Найди ожидаемый статус и тело ответа в контракте, затем напиши два соответствующих `assert`.
