# BUG-001: NUL в названии задачи вызывает HTTP 500

Статус: исправлен, регрессионная проверка выполнена.

Объект: собственный учебный Task API версии 2 в процессе разработки, не сторонний продукт. Окружение: Windows, Python 3.14.7, файловая SQLite. Влияние: отдельный некорректный ввод обходит HTTP-валидацию и вызывает внутреннюю ошибку. Приоритет учебной итерации: средний.

## Воспроизведение до исправления

1. Зарегистрировать пользователя и получить действующий токен.
2. Создать обычную задачу для контроля сохранности.
3. Отправить POST /tasks с Content-Type: application/json, Bearer-токеном и телом:

```json
{"title":"\u0000task"}
```

Ожидание: контролируемый отказ 400; существующие задачи не меняются. Правило запрета U+0000 явно закреплено в контракте версии 2 при разборе проблемы.

Фактически до исправления: 500. Автотест test_invalid_titles_leave_database_unchanged завершился на сравнении статуса: assert 500 == 400. Первый полный прогон: 1 failed, 111 passed. Это наблюдение теста, не намеренно внедрённая ошибка.

## Причина и исправление

Python проверял длину всей строки, а SQLite length(TEXT) учитывает символы только до первого U+0000. Здесь БД получает длину 0 и отклоняет INSERT ограничением CHECK. Особенность описана в [документации SQLite, length](https://www.sqlite.org/lang_corefunc.html#length).

В valid_title добавлен отказ для U+0000 до обращения к БД. Правило общее для POST и PATCH. Для PATCH добавлена отдельная проверка неизменности уже созданной задачи.

## Перепроверка

После исправления оба сценария входят в успешный полный прогон. POST с NUL возвращает 400 и не создаёт строку. PATCH с NUL возвращает 400 и оставляет прежнее название. Проверяются повторный GET и сохранённое состояние SQL. Команды и итог прогона — в test-results.md.
