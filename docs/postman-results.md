# Результаты автоматизированной коллекции Postman

Дата: 3 ноября 2026 года. Локальное окружение: Windows, Python 3.14, Newman 6.2.3. Запуск через scripts/run_postman.py с временной SQLite и отдельным локальным HTTP-сервером. База instance/tasks.sqlite3 не использовалась.

```powershell
.\.venv\Scripts\python.exe scripts/run_postman.py --iterations 2
```

| Метрика | Выполнено | Ошибок |
| --- | ---: | ---: |
| Итерации | 2 | 0 |
| HTTP-запросы | 60 | 0 |
| Assertions | 306 | 0 |

Код завершения 0. Коллекция содержит 30 последовательных запросов; число 60 учитывает повторную итерацию, а 306 включает отдельные проверки заголовков, статусов и данных. Это не количество независимых бизнес-сценариев. Длительность и время ответа не используются как результат нагрузочного тестирования.

Проверены динамические ID и токены, создание новых пользователей на следующей итерации, запрет чужих операций, неизменность данных после отклонённого PATCH, завершение сессии и повторный вход. Контрольное чтение выполняется отдельными HTTP-запросами. Эта коллекция не выполняет SQL assertions и не заменяет pytest-набор.

Ограничение base_url проверено отдельно на локальном HTTP-сервере: адрес с недопустимым путём /blocked отклонён до отправки запроса, сервер получил 0 обращений. Это проверка защитного скрипта, не часть 306 assertions успешного регрессионного прогона.

JUnit-файл reports/postman.xml генерируется заново и не коммитится. Workflow запускает тот же изолированный сценарий на Linux и загружает postman-test-results. Исторический ручной прогон с 18 запросами хранится в manual-checks.md отдельно.
