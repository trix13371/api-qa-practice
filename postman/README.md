# Postman: воспроизводимый регрессионный прогон

[Коллекция](Task_API.postman_collection.json) | [Локальное окружение](local.postman_environment.json) | [Контракт API](../docs/api-contract.md)

Коллекция содержит 30 последовательных запросов с проверками ответа и состояния данных. Регистрация, вход и создание задач подготавливают данные для следующих шагов; токены и ID автоматически берутся из ответов. Отдельные запросы зависят от предыдущих, поэтому основной способ запуска - вся коллекция по порядку.

## Покрытие

| Запросы | Сценарий |
| --- | --- |
| 01-05 | Доступность сервиса, регистрация и вход двух пользователей |
| 06-10 | Создание, чтение, изменение и отказ от частичного PATCH при неверном boolean |
| 11-17 | Запрет чтения, изменения и удаления чужой задачи; изоляция списков |
| 18-20 | Фильтр с пагинацией, отсутствие авторизации, неверный токен |
| 21-24 | Отзыв токена, повторный вход, сохранность своей задачи |
| 25-30 | Удаление, контрольный GET и завершение сессий |

Дополнительно проверяются JSON, формат ошибок, пустое тело 204, X-Request-ID и Cache-Control. Это 30 запросов, а не 30 независимых бизнес-сценариев. Полное покрытие границ и SQL-проверки остаются в pytest.

## Запуск в интерфейсе Postman

1. Запустить учебный сервис по инструкции в основном README.
2. Импортировать оба JSON-файла из этой папки.
3. Выбрать окружение Task API - local example; base_url по умолчанию http://127.0.0.1:8000.
4. Для веб-версии Postman выбрать Desktop Agent: Cloud Agent не имеет доступа к локальному серверу.
5. Открыть Collection Runner и запустить всю коллекцию, начиная с 01. Результаты смотреть в Test Results.

Имена двух пользователей создаются заново на каждой итерации; существующие записи не перезаписываются. Финальные шаги удаляют созданные задачи и отзывают текущие токены. Учётные записи остаются в учебной БД, так как API не имеет метода их удаления. На середине прогона после ошибки могут остаться тестовые задачи и сессии. Использовать только собственную локальную учебную БД.

Пароль в коллекции демонстрационный. Рабочие токены хранятся только в переменных во время запуска. Не экспортировать и не публиковать заполненные runtime-переменные или подробные JSON-отчёты с токенами. Файлы в репозитории содержат пустые значения токенов, ID и имён пользователей. Защитный скрипт принимает только http://127.0.0.1 или http://localhost; это ограничение учебного сценария, а не полноценная сетевая песочница.

## Изолированный запуск Newman

Нужны Node.js 22+ и Python с установленными requirements.txt. Из корня проекта:

```powershell
npm ci
.\.venv\Scripts\python.exe scripts/run_postman.py
```

Linux/macOS:

```sh
npm ci
.venv/bin/python scripts/run_postman.py
```

Скрипт создаёт временную SQLite, запускает отдельный HTTP-сервер на свободном порту, выполняет Newman и останавливает сервер в finally. База instance/tasks.sqlite3 не используется. При провале Newman возвращает ненулевой код; JUnit-отчёт создаётся в reports/postman.xml. Повторный запуск использует новую БД.

Проверка двух итераций в одной БД:

```powershell
.\.venv\Scripts\python.exe scripts/run_postman.py --iterations 2
```

Новая коллекция автоматизирована. [Исторический ручной прогон](../docs/manual-checks.md) с 18 запросами хранится отдельно и не выдаётся за выполнение новых 30 запросов в интерфейсе Postman.
